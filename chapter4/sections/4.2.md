## 4.2 用户特征驱动的个性化协助

本节按用户信息影响回应的主要机制比较方法。第一类把已选用户条件组织为显式画像和提示，第二类随当前任务从历史中检索相关材料，第三类将用户表示与底座模型的参数适配结合起来。三类方法都围绕同一核心问题展开：同一个请求在不同用户背景下应如何产生不同处理。

解释、建议和计划是各类路线共同面对的输出任务；候选比较与用户协商是各类方法都需要满足的交互要求。本文因此将它们纳入机制分析和统一评测框架。

### 4.2.1 基于用户画像与提示的个性化协助

上一节讨论明确问题条件下的客观回答机制，其共同假设是回应所需条件主要来自当前对话上下文与检索到的材料。然而在 Personal Agent 的使用场景中，很多协助需求依赖用户背景、偏好和使用习惯，而不是单纯的事实检索。

在表示环节，最有代表性的两条路线是 GPG 提出的引导式画像生成 [R07] 和 PQA 提出的动态画像生成与压缩 [R08]。二者的共同点在于都不直接把原始个人上下文塞进提示，而是先构造一个更适合生成的用户摘要。GPG 通过提示模型从用户历史中生成结构化的个人描述；PQA 则进一步强调画像的压缩与更新，允许根据当前任务抽取最相关的个人信息。

这两条路线的关键分歧点在于压缩方式与信息损失的取舍。GPG 将个人上下文压缩为“简洁、描述性句子”，保留自然语言的连续表述，优点是可读且方便进一步修订；PQA 更关注高相关字段和压缩后的表述，强调在高噪声历史中保留有用个人特征。两者都说明画像不是单纯记忆回放，而是有筛选和组织过程的用户状态表示。

在接入环节，两条路线都采取将画像文本置入提示以条件化生成的方式，但接入的组织粒度不同。GPG 将提炼后的画像句子整体用于生成 [R07]；PQA 则把用户画像拆成更细粒度的字段和状态条件，作为当前任务的辅助输入 [R08]。

在评价方面，可以区分两类证据。GPG 报告其在不同任务上提升了 LLM 的个性化能力，例如与直接喂入原始个人上下文相比，在预测个人偏好上提升 37% 左右；PQA 在长文本问答等任务中展示了更稳定的个性化生成效果。任务型协助场景的评价还需要专门的设置。PersonaLens 作为面向任务型 AI 助手的个性化评测基准，提供带丰富偏好和交互历史的多样化用户画像，并通过模拟任务对话评价输出是否符合用户特征。

就适用条件而言，画像—提示路线的约束可以从三方面归纳。第一，表示质量的上界由原始个人上下文决定：GPG 与 PQA 都假设存在可用的个人上下文，且需要能够提取较稳定的偏好或背景。第二，画像偏重“对当前任务可用”的信息，而非完整的个人全景，因此如何定义压缩保留边界非常重要。第三，过度压缩可能损失细节，导致本轮回答看似个性化，实则忽略了具体动机或上下文变化。

画像提示为个性化协助提供了可读的条件表示，GPG 和 PQA 分别说明引导提炼、领域组织与压缩可以改善个人信息的利用。[R07][R08] 后续评价已经覆盖偏好预测和长文本生成等任务，但在 Personal Agent 场景中还需要进一步判断其是否支持用户计划、解释和决策的具体协助。

### 4.2.2 基于用户历史检索的个性化协助

个性化协助的一个核心问题是：模型在回应“帮我安排学习计划”或“我该怎么回导师”这类请求时，应该引用哪段历史，以及这些历史应如何改变当前方案。

这一机制的代表性工作可以从 LaMP 说起。需要先区分两个层面：LaMP 本身是一个用于训练和评估个性化输出的 benchmark，包含七个个性化任务，覆盖三个层次：偏好、过去行为和人格相关表达；LaMP-QA 则将类似思路推进到长文本问答场景。该 benchmark 面向个性化长文本答案生成，覆盖艺术与娱乐、生活方式与个人发展、社会与文化三大类共 45 个以个人偏好为核心的问答样本。

从“如何选择历史”的角度看，上述两项工作分别提供了不同维度的约束。LaMP 的检索模型比较体现的是相关性维度：用词项匹配还是语义匹配去对齐目标与历史；LaMP-QA 更强调长文本背景如何用于生成个性化回答。二者共同提示，一段历史如果不与当前任务匹配，就不能作为个性化生成的有效前提。

然而，这些 benchmark 主要评测的是记忆或个性化能力，不能直接等同于协助效果的证明。LoCoMo 的数据可以说明长期历史本身的难度：其对话平均包含 600 多轮、跨多个月的上下文，长期记忆检索因此比短期对话更容易出现不一致、遗忘和误用。也就是说，历史检索不仅需要“找得到”，还需要“找得对”。

历史检索的协助效果应在任务层面检查。LaMP-QA 关注生成答案与人类偏好的一致性，PersonaLens 则通过模拟任务对话联合评价个性化、回应质量与任务结果。在更接近 Personal Agent 的动作与计划任务中，候选方案的个性化价值必须以最终产物为核心：例如网页协助中重点看函数参数是否被更准确地填充，学习计划中重点看建议是否与用户知识基础和时间约束相匹配。

历史检索的评价需要同时检查是否找对了用户材料，以及这些材料是否被忠实使用。用户偏好不应覆盖客观事实，检索得分与最终回应质量也不是同一个维度；系统可能找到相关历史，但仍可能把它用于错误的推断或过度泛化。PersonalWAB 与 Behavior2Trip 这类工作进一步提示，历史选择需要和下游行动相连：如果检索到的用户背景不影响工具选择、参数设置或计划制定，那么它就不能被视为真正有用的个性化依据。

综合来看，基于用户历史检索的个性化协助的适用条件可以概括为：任务确实依赖用户特有的背景（如个人日程、过往讨论、既有偏好）；历史中存在可识别的条件与证据；且当前协助要依赖这些条件来决定方案差异。对 Personal Agent，这意味着历史不是泛泛“记住用户”，而是“当前回应需要、且当前回应可被追溯的材料”。

### 4.2.3 基于用户表示与模型适配的个性化协助

在 4.1 所处理的明确问题直接回应之外，个性化协助的核心问题在于：相同的请求在不同用户背景下应有不同处理。以“帮我安排学习计划”这一分析例子为例，用户 A 是已有基础、希望高强度效率提升；用户 B 则更在意认知负担和可持续性。两者的最优协助并不相同，问题在于如何把用户表示转化为生成策略。

第一条路线以 PPlug [R09] 为代表。其摘要指出，为每个用户单独微调一个个性化 LLM 代价过高，难以普及；而检索式方法将用户历史中相关文本作为示例，放到提示中进行个性化生成。第二条路线则以 Chameleon（Fake it then Align it）[R10] 为代表。其摘要同样指出逐用户微调成本过高，并补充了检索式路线的另一约束：检索方法依赖大量额外历史和有效规则，而个性化模型需要在真实用户行为和期望行为之间做对齐。

PUMA 展示了历史检索与参数级对齐的组合：任务相关记忆先提供当前条件，监督微调与直接偏好优化再适配模型的动作生成。[R36] 它与 PPlug 的输入嵌入方式相比，更强调将用户历史转化为可供模型优化的训练信号，而不只是在推理阶段做提示增强。三者共同说明，个性化可以发生在输入层、表示层和参数层三种位置。

比较两条路线，可以提炼出若干适用条件。在用户数据需求方面，PPlug 需要对用户全部历史上下文建模，数据数量、连续性和噪声都会影响表示；Chameleon 则通过生成偏好数据降低逐用户采集代价，但仍要求存在可用的偏好建模目标。不同机制在“训练成本、数据要求和输出稳定性”上存在明显差异。

评价方面，PPlug 与 Chameleon 在 LaMP 上的任务指标支持其各自设定下的个性化收益，不能直接证明多轮协助的有效性。[R09][R10][R11] PersonaLens 的模拟任务评测提供了更接近真实协助场景的参考，但仍需结合实际用户反馈进行校正。表示接入与模型适配都需要检查事实性风险。PERG 将事实准确和偏好匹配作为联合要求，这为评价个性化收益提供了补充维度。[R15] 对学习计划等协助任务尤其重要，因为错误的历史利用可能让回答看似贴合用户，但在事实层面已偏离真实信息。

表示接入、表征编辑与参数训练提供了不同的个性化位置。PPlug 保持底座参数不变，以用户嵌入接入历史；Chameleon 使用自生成偏好数据与表示编辑；PUMA 进一步说明参数适配可以强化模型对用户偏好的长期稳定性。对 Personal Agent 而言，这些机制并非互斥，而是可以在不同责任边界中组合：例如先用记忆与画像提供“当前输入条件”，再用少量偏好数据修正输出策略。
